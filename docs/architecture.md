# 部署与数据归属建议

以下为讨论中的候选设计，尚未实现。Codex 订阅后台运行方式和开源底座必须先验证。

## 运行链路

```text
手机浏览器
  → 剪辑平台：工程、素材上传入口、要求、进度、对话
  → 服务器后台任务
  → Codex 分析素材并驱动开源剪辑工具
  → 剪辑引擎渲染、检查、修正
  → 成片回传点播平台
  → 手机预览、下载、继续修改
```

手机关闭页面后，已提交任务仍应由服务器继续处理。Codex、素材处理和渲染均运行在服务器；Mac 不作为产品运行依赖。

## 数据保存

| 数据 | 归属和建议位置 |
| --- | --- |
| 平台代码、默认规则、场景模板、部署配置 | 本仓库，Git 版本管理 |
| 账号长期偏好 | 剪辑平台自己的数据库，跨工程复用 |
| 工程、素材关联、时间线、对话、任务状态、版本 | 剪辑平台自己的数据库或所选开源引擎的持久化工程存储 |
| 本次采用的规则和偏好 | 工程保存版本或快照，避免偏好更新改变旧工程 |
| 原视频、各版成片 | 复用 video-2022 的视频存储，剪辑平台关联视频 ID |
| 临时素材副本和渲染中间文件 | 服务器任务工作目录，清理时不删除可恢复工程所需的持久化内容 |

数据库具体选型未定。此前本地 Mac SQLite 的建议已不适用于最终部署目标，不应直接照搬。

偏好优先级建议：本次明确要求 > 个人偏好 > 默认规则。用户说“这条换音乐”只影响当前工程；明确说“以后都这样”才更新长期偏好。个人运行数据、登录凭证不得提交公网仓库。

## 复用 video-2022

本次在现有代码/文档中查到以下接口；部署可用性和授权行为未实测：

| 接口 | 已有用途 |
| --- | --- |
| /video/create | 创建视频记录 |
| /file/getUploadCredentials | 获取 OSS 临时上传凭证 |
| /file/uploadFinish | 通知文件上传完成 |
| /video/rawFileUploadFinish | 通知原片完成并进入后续处理 |
| /video/getRawFileDownloadUrl | 获取原视频下载链接 |

上传可复用浏览器直传 OSS 的已有路径。点播平台保存文件及视频元数据；属于哪个剪辑工程、为何选取某段、修改了什么由剪辑平台管理。

需验证素材入库是否触发不必要的点播转码、素材访问权限，以及成片下载至相册的实际操作。新需求不能因复用接口而无意变成公开视频发布。

## 模型、GPU 与调度

- 用户只有 Codex 订阅；先验证服务器 Codex CLI 登录和执行，不能假定可直接调用模型 API。
- 订阅可用模型、额度、登录持久性和后台任务可靠性尚未验证，不能承诺固定模型或无限运行。
- 剪辑引擎负责裁切、字幕、混音和导出；模型负责理解、规划及工具调用。
- GPU 用于实际需要的计算加速；不能用 GPU 替代正确的素材理解和剪辑规则。
- 如服务器渲染性能不足，可评估阿里云函数计算 GPU。产品、规格、费用和部署方式尚未选定。
- 第一阶段先使用简单后台任务执行方式；Multica 是否有价值待后续规模决定。
