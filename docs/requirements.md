# 讨论记录与需求基线

记录日期：2026-09-16。

## 用户目标

用户已有 AI 剪辑的游泳视频，认为剪辑速度快、大方向正确、覆盖动作的能力已经有价值，希望将经验沉淀成平台。主要使用入口是手机，计算和任务运行必须在服务器完成，不依赖 Mac。

## 五项需求

1. 上传多段素材，并组织为同一个剪辑工程。
2. 按自然语言要求和规则自动剪辑，生成成片。
3. 持续积累规则、个人偏好和反馈，供后续工程复用。
4. 手机上预览、下载、保存成片，用于用户手动发布抖音。
5. 第二期通过对话修改已有工程，生成新版并可回退。

自动发布抖音尚不在范围内。多用户商业服务、复杂手动时间线编辑器尚未确认为需求。

## 对现有成片的反馈

用户肯定：剪辑很快，大方向符合初衷，体现不同泳姿，证明 AI 能完成工作。

用户指出：

- 蹬壁出发不是泳姿，不应作为泳姿单独并列。
- 姿势之间切换过硬，希望字幕先行、整体节奏慢一点。
- 现场讲话与实际展示动作可能不在同一时间点。
- 倾向去掉原声，改用后期配音或音乐。

待样片验证的规则建议：保留完整动作周期；镜头停留和段落衔接先调整，再决定是否慢放；区分下一段预告与当前动作标签，避免字幕提前导致错误标注。

尚未决定：泳姿展示还是更广泛的游泳技能合集；默认音乐还是旁白；字幕提前量、各段时长、转场方式。不得将推荐值当成已确认要求。

## 三个阶段

| 阶段 | 目标 | 验收 |
| --- | --- | --- |
| 准备 | 验证已有点播链路、Codex 订阅执行路线、开源候选 | 手机上传和成片保存可用；服务器完成一次真实剪辑 |
| 第一期 | 上传素材到自动成片 | 手机上提交要求后可查看进度、预览、下载符合确认规则的成片 |
| 第二期 | 对话修改 | 按指定反馈修改对应片段、字幕或音轨，保留工程版本并可回退 |

## 讨论中的重要修正

- 拒绝将剪辑任务和工程记录放进 video-2022：点播与剪辑是独立平台。
- 拒绝依赖 Mac 运行：服务器处理，手机使用。
- 不采用默认需要 OpenAI API Key 的设计：用户只有 Codex 订阅。
- 优先开源复用，经真实素材验证后选择，不先重写完整平台。
- GPU 不是已确定依赖；用户允许需要时使用阿里云函数计算 GPU，以实际效果为目标。
- Multica 不是第一期已确定依赖。
