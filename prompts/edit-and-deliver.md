# 剪辑、交付与反馈更新提示词

用于本项目执行任务，不代表手机自助平台已经完成。具体题材要求优先于本模板。

```text
先读项目 AGENTS.md、docs/autonomous-editing.md、最近需求记录和对应题材提示词，再检查现有工程与文件。不要凭对话记忆猜测前任做到了哪一步。

1. 分清原素材、参考片、旧成片。记录每项独有内容和来源区间，检查连续动作；标明抽帧间隔与观察范围，不能把稀疏联系表说成完整逐帧播放。
2. 按内容组织镜头。同类动作放在一起，保留完整动作和不同角度的必要差异。无法确认技术名称时用准确的可见动作描述，不补造不存在的泳姿或内容。
3. 动作展示从最新已确认的题材模板开始：每组动作一个固定名称、无预告；字幕大小、底板、转场和混音按最新反馈配置，本次见游泳题材模板：每个片段有顺序编号和进出动画，旧的无动画规则已被替代。不要把验证特效的 demo 当成用户风格。
4. 先检查若干字幕与衔接样例，再完整导出。声音、画幅、字幕及编码参数写入方案。本次最新反馈要求不要配乐，恢复教练原声；直接从原素材取同期音轨，检查讲话音量与峰值。
5. 检查完整解码、时长、尺寸、音轨和内容覆盖；复核各段字幕及全部剪口。机器检查、抽帧审查、完整播放、手机实测分别记结果。
6. 用户要求手机观看时，按授权上传最终版本到 video-2022 或专用私有 OSS；复用已有存储和账户，不因旧提示词重复创建 bucket 或 RAM 用户；凭据仍由 Infisical 管理。保存私有交付回执，失败时复用已创建记录。等 READY 后实际检查 HLS 和首尾片段；最后给播放页链接，不以本地路径或上传成功代替可播放。
7. 用户提出明确修改意见时，主动同步项目提示词、流程、必要代码和验证，并记录旧规则被什么反馈替代。项目风格改进可以持续积累，单片音乐或时长不能自动变成其他工程的强制规则。
8. 不覆盖旧版文件，不提交私人素材、签名链接、凭证或运行回执到 Git。代码提交和推送按用户授权执行；合并 PR 需要明确授权，不能从“提交 PR”推断。
```
