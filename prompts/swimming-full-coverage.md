# 完整覆盖素材的游泳剪辑提示词

更新：2026-09-18。本次是10节课的学习成果展示，用于抖音推广。最新反馈要求每个片段有入场出场动画、序号、大字幕和底板；09-18后续修改明确不要配乐、教练原声要听清，替代此前音乐加低音量原声。声音处理仍按本次素材与要求决定，不自动修改账号全局偏好。

```text
请将提供的所有素材剪成一条完整的游泳动作展示视频。核心要求是：每一种不同的动作或教学内容都要展示到，不能为了时长只选几个精彩片段。

一、先分析素材
先区分原素材与参考样片。参考片只帮助理解要求，不自动纳入成片；除非本次明确允许使用其镜头。
逐段查看所有视频，列出：
- 素材中有哪些动作或教学内容。
- 每项内容对应的文件和起止时间。
- 哪些是重复展示，哪些是独有内容。

不要仅凭文件名、现场讲话或单张截图判断动作；结合连续画面确认。无法确认的动作不要随意命名。

二、保证内容覆盖
- 每一项独有内容都必须在成片中出现。
- 同一种动作的重复片段可以合并，选取最清楚、最完整的一段。
- 同一动作如果展示了不同角度或不同教学要点，应保留这些差异。
- “覆盖”意味着观众能看清动作，不能用一闪而过的镜头充数。
- 保留完整的动作过程；周期性动作尽量展示至少一个完整周期。
- 如果目标时长容纳不下全部内容，先说明冲突，不得擅自删掉某一项。

三、正确分类
区分泳姿、出发、转身、辅助练习和其他水中技能。
蹬壁出发不是一种泳姿，可以保留为出发技巧或对应泳姿的起始动作，但不能与泳姿并列计数。
本片要求覆盖不同内容，不代表要把所有内容都叫作“泳姿”。

四、安排节奏与字幕
- 将同一种动作的镜头安排在一起，形成容易理解的顺序。
- 节奏舒缓，给观众看清动作的时间，不要频繁抢切。
- 尽量在动作完成或自然停顿处切换，避免截断关键动作。
- 一个动作只保留一个固定名称。同类连续镜头保持相同动作名称；每段序号独立更新，按本次反馈分别进出，不因角度变化改成多个动作名称。
- 不显示“接下来”预告，不轮换分类小字与动作名称。对照参考片与画面核准术语，不能只写模糊的动作描述或照抄俗称。
- 动作名称放大，并加半透明底板。本片采用大号白字、深蓝底板，避开人物与手机界面区域；每个片段标题交替滑入回弹、滑出，并显示顺序编号。序号不改变教学名称，也不表示动作种类数量。
- 一个动作完整展示后再切到下一个；不同镜头可交替采用短滑动、擦除转场，镜头首尾短推拉，只占动作证据之外的余量。同源连续片段保持连续，不人为制造转场。
- 分类保存在清单和方案里，不必全部叠在画面上。画面名称与正在展示的动作对应。
- 不靠统一慢放或特效解决节奏问题。先检查动作完整性、片段组织和停留时间。

五、声音
本次不添加任何配乐，保留原素材中的教练讲话及同期现场声。原声不再按配乐背景声的低音量处理；检查讲话音量与峰值，必要时提升响度并限制峰值，避免削波。不得将原声先静音再从旧混音成片提取，必须直接使用原素材音轨。原声与对应镜头保持同步，现场讲话内容仍不作为动作时间的唯一依据。
如另行要求配音，应先确定画面，再按实际动作时间编写和对齐旁白，不沿用错位的现场讲话。

六、成片检查
导出前逐项核对最初的内容清单：
- 每项独有内容是否都有清楚、完整的展示。
- 动作分类、字幕名称和画面是否一致。
- 有没有过短镜头、关键动作被截断或切换过急。
- 有没有黑帧、字幕遮挡或音轨异常。
- 是否还存在频繁换字、同类内容重复换标题、预告、字幕不可读或转场重影。

先抽查字幕布局与典型衔接，再导出整片；导出后检查各段和每处衔接，不能只看开头。

交付成片时附一份覆盖表：
“内容名称 → 原素材时间段 → 成片时间段”。

如果有内容因模糊、遮挡或素材不完整而无法清楚展示，明确列出原因，不得声称已经完整覆盖。

七、手机交付与反馈
本地文件只是剪辑产物。用户要求上传 video-2022 后，要上传本次最终版本并等待 READY，检查播放列表和首尾视频片段，再给手机可打开的播放页链接。
上传返回成功不等于可以播放；不要将电脑路径作为手机交付。
出现新反馈时，修改本片并同步项目提示词、流程和必要代码，记录替代了什么旧规则；保留旧工程版本，不覆盖旧成片。
```

## 交给本仓库执行

从 `examples/animated-numbered-plan.json` 起步，本片使用 `caption_style: badge`、`number_clips: true`、`motion_style: energetic`、`encoding_profile: compact`、`next_label_seconds: 0`、`audio.mode: source`。转场按完整动作之外的余量设置，不能机械套用固定值。这些是可复用配置，不要再临时替换 Python 函数来改字幕。

请把分析结果转换为 `schemas/edit-plan.schema.json` 定义的方案，再按 `docs/agent-handoff.md` 和 `docs/delivery.md` 运行。类别、证据、音轨与参考角色必须落到结构化字段。清单完整性和名称正确性仍由审片确认，不能把验证器通过当作视觉理解通过。
